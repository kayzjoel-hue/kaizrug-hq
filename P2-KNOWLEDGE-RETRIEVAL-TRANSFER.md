> **Declared ≠ implemented ≠ committed ≠ deployed ≠ runtime-observed ≠ customer-used ≠ revenue-proven.**

`Notion Project Record → Canonical GitHub Repo → Commit → Deploy → Runtime → User/Transaction → Evidence → Revenue`

## 7. Retrieval Discipline

Use this sequence for each unresolved asset:

`DISCOVER → FETCH → CROSS-CHECK → CLASSIFY → RECORD → EXECUTE → VERIFY`

### Discover
Search Notion and GitHub for the exact project/repository/link/workflow.

### Fetch
Read the relevant page, README, configuration, source file, workflow, or deployment record.

### Cross-check
Compare claims across Notion, GitHub, deployment providers, and runtime evidence.

### Classify
Use one of:

- CANONICAL
- SUPPORTING
- EXPERIMENTAL
- DORMANT
- LEGACY
- DUPLICATE
- UNKNOWN

### Record
Write the result into the canonical registry/evidence record.

### Execute
Only make implementation changes when the evidence establishes the correct owner/path.

### Verify
Require direct runtime or workflow evidence before upgrading status.
